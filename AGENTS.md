# All Agents
Any README.md files you see may not be up to date. Do not treat them as a source of truth. Instead, read through the codebase yourself to understand the current structure and functionality.


If a file says at the top for it to not be edited by you (or by agents in general), do not edit that file, even if it results in failed tests. Instead, describe why you might have wanted to edit that file in your report.


If code is training or using a neural network, you should likely be using GPU. If you can't use the GPU and you haven't been given explicit permission to use CPU for neural-network-related work, stop immediately and ask the user for permission. When training networks, use TQDM. If training time is estimated to be 1-hour or longer, stop the training and either rebuild your code to take less time or stop your task and describe to the user why the task cannot be completed without >= 1 hour long runs.


Before coding anything, run the test suite (if it exists) and note what tests pass and what tests fail. Your code should likely cause more tests to pass after you finish, but not all tests must pass, especially if they didn't pass initially, or your code indicates that the test cases are wrong in some way. DO NOT EDIT ANY TEST CASES UNLESS YOU ARE SPECIFICALLY ASKED TO.


Any code you add should pass Pylance (at default "standard" level). Use `cast` as needed rather than `# ignore` to deal with Pylance warnings.


For each task that you complete or question that you answer, write a `YYYY-MM-DD-(HH:MM)-name-of-report.md` report with a descriptive name inside `agent_explain/` documenting
  1. The current date
  2. The current time in UTC
  3. Your (agent) name and what model you are powered by
  4. A summary of what you did
  5. The exact words of what the user asked you to do.
  6. A list of everything you did while attempting to accomplish what the user asked. For each item in the list, explain why you did it, what other options (if any) you considered or attempted that didn't work, and any other information you think might be helpful for fully explaining your work and reasoning
  7. Useful data and any other information that may be helpful for agents or humans who may attempt to build upon your work later
  8. Any questions you may have for the developer.
   
ANY PROPOSED CHANGES OR ANSWERS YOU MAKE WITHOUT A PROPERLY NAMED AND FILLED OUT REPORT WILL BE REJECTED. ALWAYS WRITE A REPORT.

Only use Pytorch, not Tensorflow.

## Codex CLI (Local OpenAI Agent on WSL)
You should be running on a local computer using WSL. Double-check to ensure that this is the case by running `uname -a` and ensuring it shows WSL before continuing.


Also check to ensure that you are in a sandboxed environment by verifying that the root directory has a folder called `workspace` and seems to be the sort of environment that would be generated by `.devcontainer/devcontainer.json` rather than a full computer.


There are multiple different versions of this agent: Chat, Agent, and Agent (full-access).


The Chat agent uses a read-only environment.
The Agent (full-access/not full-access) agent doesn't have a read-only environment.


Please safely determine which version of the agent you are by merely reading your configuration details, then follow the corresponding instructions.


### Chat agent (read-only)
Do not attempt to write a report since you don't have write access. Your response will suffice as your report.


### Agent agent (full-access/not full-access)
Use the venv located at `.venv`. Please initialize this immediately. If you need any packages or need to install any packages, please use this virtual environment.
If `torch.cuda.is_available()` returns `True`, you are a full-access agent.
If it fails due to a `Error 304: OS call failed or operation not supported on this OS` error, then you are not full-access.
If it fails due to any other error, stop all tasks immediately and report what went wrong.


## OpenAI Codex (Cloud Version, not running in local .devcontainer)
You should have access to the internet. If you try to run something and it fails due to not having a module installed, please just install that module.


If it exists, you should install the requirements in the file `openai_codex_requirements.txt` if they aren't already installed. Again, feel free to install any other components (including ones not listed) that you need to fully complete your task.


Use Pyright (or Pylance) to check type-hinting and add in appropriate types. After you are done with your task, please double-check that you pull in recent changes and that your code still works with those changes. If you did any complex merging during this process, please explain what merging you did.
